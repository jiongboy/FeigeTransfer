# 飞鸽快传 macOS 客户端

本项目位于 `Project/MacOS/`，与 `Project/Windows/` 客户端共用协议及开发规范；两个平台使用同一 `main` 主线。

Swift 6 / SwiftUI，最低 macOS 13，通过 Swift Package 构建。当前版本 **0.4.0（构建 7）**，功能与 Windows 1.2.x 对齐。

```sh
cd Project/MacOS
swift build
swift test
swift run
```

## 使用

启动时读取设备身份并执行一次真实签名检查，准备完成后才开放设备发现和连接。**整个过程不弹出钥匙串密码窗口**，也不需要输入 Mac 登录密码。握手等待签名证明单独保留最多 5 分钟，避免另一台设备还在准备时被旧的 15 秒总期限中断。

### 设备身份如何保存（不弹钥匙串密码）

旧版本把 RSA 私钥存成系统钥匙串的 `kSecClassKey` 项。这类项必然绑定访问控制列表（ACL），除非进程具有 Apple 签名的稳定身份，否则系统会弹出“想使用您储存在钥匙串中的机密信息”并要求输入登录密码；用 ad-hoc 签名时每次重建都会让它重新询问。

现在改为：

| 组成 | 位置 |
| --- | --- |
| 私钥密文 | `~/Library/Application Support/FeigeTransfer/Identity/identity.pkcs1.bin`（AES-256-GCM 加密，权限 600） |
| 32 字节加密密钥 | 钥匙串 *通用密码项*（`com.feige.transfer.identity` / `identity-wrapping-key`），走数据保护路径，**不经过 ACL 授权** |

不弹窗的原因是不再创建 `kSecClassKey` 项，而不是去绕开系统授权。加密密钥所在的通用密码项本身不要求交互密码。

从旧版本升级时会在首次启动自动迁移：读出旧的钥匙串私钥，加密写入新位置后删除旧项，**设备指纹保持不变**，对端不会把本机当成新设备。旧的钥匙串项若因权限无法读取，会在应用日志记录，然后生成新身份（对端会看到新设备，需重新同意连接）。

**明确的取舍**：私钥不再受不可导出的钥匙串保护，以同一登录用户身份运行的程序理论上可以取出它。这里权衡的是“每次都要输密码”与“本机同用户程序可读”。设备身份只用于在局域网内向用户自己的设备证明身份，不用于签发软件、不保护静态数据；正式软件签名与更新签名是另外的证书和密钥。

### 签名与钥匙串

应用使用 Developer ID / Apple Distribution 证书签名（`scripts/package-app.sh` 会自动选择，也可用 `FEIGE_SIGN_IDENTITY` 指定）。稳定签名身份不只是分发要求：ad-hoc 签名下系统按代码哈希识别应用，每次更新都变成“陌生程序”，准备阶段会长时间卡在等待授权。

1. 首次启动通过“本机设置 → 准备连接”两步引导设置设备名称与接收文件夹；可稍后继续，进度会保留。确认后再准备设备身份并启动网络。应用自动发现局域网中的同版本设备。
2. 选择左侧设备并请求连接，也可手动输入对端 IP 和端口。
3. 对方点一次“同意连接”，即可在同一个会话里聊天、发送图片与文件。收到文件时卡片会先显示“等待你确认接收”，可点“接收”或“拒绝”；拒绝不会在本机创建任何文件，确认等待最多 2 分钟。
4. 文字 Enter 发送、Shift+Enter 换行；支持系统输入法、文字复制粘贴。输入区“表情”按钮打开内置表情面板（不依赖系统 ⌃⌘Space 是否开启）。草稿按会话保存在本机，切换设备或重启后仍在，发送成功后清除。图片与文件可选择、拖入输入区；剪贴板中的图片也可在输入区按 ⌘V 粘贴发送。附件卡片可预览图片、PDF、DOCX 正文和常见文本/源码；图片可缩放，源码预览带行号与基础语法着色（注释、字符串、数字、关键字，与 Windows 使用同一套规则，超过 2 万字符自动转为纯文本以保证滚动流畅），文本与 DOCX 预览均为只读并有大小、行数限制。DOCX 只提取正文段落、换行和制表符，不解析复杂排版或运行文档内容。文件卡片可打开文件或在访达显示。
5. 文件传输期间仍可聊天，双方可同时传文件。文字收到对端回执后显示“已送达”。失败的已发送消息可在重新连接该设备后重试。

无产品文件大小上限，支持空文件；实际大小由文件系统和可用磁盘空间决定。图片按原图发送，不压缩。单条文字最多 8 KB UTF-8，长文可作为文件发送。

取消传输会断开连接并清理未完成文件，已完成文件保留。重试文件重新发送，不支持断点续传。一次只连接一台设备；其他设备历史可查看，发送控件只对已连接会话可用。

本地保存最近 1000 条已结束会话消息；重启后未完成消息标记为失败。旧版文件历史从“传输记录”查看。图片预览依赖原始文件仍在本地；不支持的图片格式保留文件卡片。保存或更改接收目录时会清除目录中符合 Feige 专用命名规则的孤立未完成文件，不触碰普通文件或符号链接。暂未提供群聊与离线投递。

会话列表右键可打开、隐藏或删除会话记录；隐藏会话可在偏好设置中恢复。删除前会确认，不删除已接收文件或独立传输记录；活动连接和未完成传输不能删除。新消息或重新连接会恢复隐藏会话。

遇到连接失败时，可从错误提示打开“连接排查”，查看局域网、VPN/TUN、路由器隔离及防火墙检查方法；侧栏“使用帮助”提供完整连接步骤并可打开防火墙设置。应用保留原始错误，不会自动修改系统代理、防火墙或路由设置。网络变化（切换 Wi-Fi、插拔网线、VPN 启停）后会自动重建设备发现，已建立的连接、监听端口和连接同意保持不变。

## 偏好设置

“飞鸽快传 → 偏好设置…”（⌘,）或侧栏齿轮打开同一个设置窗口，卡片与 Windows 设置页一一对应：

| 卡片 | 内容 |
| --- | --- |
| 设备名称 | 保存后立即重新广播；改名不改变设备指纹、不合并历史 |
| 接收文件夹 | 选择并保存；保存时清理本应用遗留的未完成暂存文件 |
| 本机连接信息 | 就绪状态、局域网地址与端口、手动连接说明 |
| 版本与更新 | 当前版本/构建/渠道、检查更新、自动检查开关、下载与安装、跳过此版本、更新说明 |
| 通知（可选） | 启用/关闭通知、发送测试通知、打开系统通知设置 |
| 本机记录 | 记录数量、清空传输记录（不删除文件与会话）、打开数据目录 |
| 隐藏的会话 | 逐项或全部恢复 |
| 设备身份与连接安全 | 可核对的设备指纹 |
| 应用运行 | 后台运行说明与“退出应用” |

首次连接、首次收发成功、关闭窗口后仍后台运行、通知邀请等提示以可关闭提示条显示在主窗口顶部，与 Windows 的 InfoBar 等价；通知邀请接受或跳过后不再重复。

## 通知

通知是可选项，失败不影响收发。首次收发成功后会邀请启用；也可以在偏好设置中启用并发送测试通知。系统拒绝后在“系统设置 → 通知”中重新允许。

## 应用更新

更新流程遵循[应用更新规则](../Docs/Public/UpdatePolicy.md)：后台静默检查（每 24 小时最多一次）→ 用户确认下载 → 校验大小与 SHA-256 → 用户确认安装 → 等待收发结束 → 验证签名并原子替换应用 → 重新启动。自动检查不会下载、安装或弹出对话框。

- 清单地址为 `<base>/macos/<channel>/feige-macos-update.json`。当前来源优先接入与 Windows 相同的局域网服务器 `http://192.168.50.229:8080/updates`；只在配置显式允许、且地址匹配固定主机和端口时接受 LAN HTTP。包和说明链接必须同协议、同主机、同端口并位于该来源目录下。
- 更新清单为签名 JSON，结构为 `format`、`keyId`、Base64 `payload`、Base64 `signature`；签名原文为 `Feige.Update.v1\\n<keyId>\\n` + payload 原始字节。仅信封结构与 Windows 共用，签名算法为 macOS 侧 P-256（ECDSA/SHA-256，CryptoKit 校验），也接受 Ed25519。Windows RSA 公钥不能用于 macOS 清单。
- 信任根随签名后的应用一起分发：`Resources/Updates/UpdateSource.json`。当前已配置独立 P-256 公钥 `feige-macos-release-2026`，私钥保存在仓库外的本机受限目录中。macOS 更新目前使用固定局域网来源；Windows 的 GitHub 回退尚未配置为 macOS 来源。
- 安装前先用 Security 框架验证当前应用与新包的代码签名，再用同目录重命名方式替换应用，移除旧版本失败时回滚；开发构建（非 `.app`）拒绝安装并提示从正式安装包更新。
- 发布签名工具：`scripts/sign-macos-manifest.py`（需要 `cryptography`；私钥不得进入仓库或 `Release/`）。

```sh
./scripts/sign-macos-manifest.py keygen --key-id feige-macos-release-2026 --out ~/.feige/macos-release.pem
./scripts/sign-macos-manifest.py public-key --key ~/.feige/macos-release.pem   # 填入 UpdateSource.json 的 publicKey
./scripts/sign-macos-manifest.py sign --key ~/.feige/macos-release.pem \
    --key-id feige-macos-release-2026 --payload payload.json --out feige-macos-update.json
```

关闭主窗口后应用继续运行，点击 Dock 图标可重新显示主窗口；也可通过“文件 → 显示主窗口”（⌘1）打开。最小化窗口会恢复显示，重复打开不会创建多个主窗口。退出应用仍使用 ⌘Q。

## 本地预览包

```sh
./scripts/package-app.sh
```

生成仓库根目录同级 `Release/MacOS/0.4.0/飞鸽快传.app` 与 `Release/MacOS/0.4.0/FeigeMac-0.4.0.zip`。交付输出位置由仓库根目录定位，与从仓库根目录或本目录启动脚本无关。打包前会从 `Project/Ui/Branding/FeigeIconV1/Feige.icns` 安装正式应用图标，再执行签名。脚本优先使用可用的 Developer ID Application 证书，其次使用 Apple Distribution；没有证书时才回退 ad-hoc。Apple Distribution 和 ad-hoc 包不能替代 Developer ID 公证分发：

```sh
FEIGE_SIGN_IDENTITY='Developer ID Application: ...' FEIGE_NOTARY_PROFILE='已有凭据名称' ./scripts/package-app.sh
```

两端均需更新到 v3。Windows v3 客户端已完成，已有 Windows↔Mac 基本互通反馈；完整实体双机矩阵、原生界面完整操作、公证及干净机器安装仍待[验收](../Docs/MacOS/AcceptanceChecklist.md)。macOS 局域网更新清单与 build 11 已发布到 Mac mini；本机完成 build 9 → 10 的更新流程验收，并从 build 10 升级到 11 后验证“更新完成”提示可关闭。公网 GitHub 回退、Developer ID 公证及 Mac mini 客户端安装尚未验收。
