# Windows 1.2.0 交付说明

日期：2026-10-24。范围：统一主线迁移前的 Windows 源码、自包含 EXE 测试安装包，协议 v3。本说明记录 1.2.0 已交付内容，并单列交付后尚未打包的源码改动；历史实现与逐轮验证仍保留在 [Windows 开发日志](DevelopmentLog.md)。跨平台公共更新日志继续由 main 维护。

## 近期修改

- **窗口与布局**：沿用 1.1.1 扩大的 10 个逻辑像素缩放感应带，支持四边/四角拖动。三栏界面整合导航、设备会话和聊天；左侧图标与标签统一左对齐，窄窗口可切换列表与聊天。设置页集中本机地址、端口、指纹与退出入口，不加入搜索 UI。
- **消息与附件**：优化完成后的文件气泡，统一格式、大小、送达标记、打开和显示位置入口；失败保留原因及重试。应用内支持图片缩放、代码行号/基础着色与复制、常见文本、PDF 翻页及 DOCX 正文预览，不执行文件中的代码或上传文件；不支持的格式保留系统打开入口。
- **会话管理**：按最近活动排序并显示摘要，支持右键打开、隐藏、删除记录；设置中恢复隐藏会话，新消息/重新连接可重新显示。删除需要确认，不删除磁盘文件和独立传输记录，活动连接/传输先结束再删除。
- **首次安装**：按 main 引导方案接入“本机设置 → 准备连接”两页，支持返回、重试、稍后设置与进度恢复。旧资料兼容，损坏/未知资料保留并提供修复入口；真实首次收发后邀请通知。交付时自动检查更新仅保存偏好；更新服务后来接入 Mac mini LAN 的改动属于交付后源码，见 [当前更新接入状态](UpdateService.md)，不属于 1.2.0 包。
- **网络连接**：发现保留多个有效局域网候选地址，TCP 连接失败可回退；网络变化/刷新重建发现，尽量保留仍有效的会话。发现不可用时保留监听与手动连接，细化代理、多网卡、IPv6 范围及多层路由说明。
- **失败排查**：超时、不可达、套接字拒绝/重置等错误保留原原因，条件提示检查 VPN/TUN/透明代理的局域网绕过/分流规则，提供“连接排查”。不声称检测到代理或确认其为原因，不给取消、对方拒绝连接请求、身份/协议及磁盘错误追加代理建议，不修改系统网络设置。
- **图标与交付**：统一使用已确认的白鸽蓝青 v1 图标；母图、ICO、ICNS、配套说明纳入源码。主程序版本为 1.2.0，MSIX 清单同步为 1.2.0.0；此历史交付文件当时保存在 `download/`（现 `Release/Windows/1.2.0/`）；新仓库交付包使用 `Release/Windows/<版本号>/`，且不提交 Git。

预览格式、文件大小与行数限制详见 [Windows 使用说明](../../Windows/README.md)，实现边界见 [开发手册](DeveloperGuide.md)。

## 交付后源码改动（尚未重新打包）

- **名称同步**：收到同一 v3 实例的新名称时，同步已有会话列表、聊天标题、头像及输入提示；TCP 等待期间更名，下一次入站握手读取当前名称。发现名称仅作显示提示，不改变完整身份指纹、历史消息和连接同意。
- **刷新反馈**：刷新按钮显示进度环，设备区显示查找中及完成时间；禁止重复点击，等待首批异步响应后显示已刷新、未发现或失败状态，后台发现继续运行。
- **签名准备**：补齐应用未签名 EXE/DLL、安装器内部临时副本及卸载器签名；保留并验证厂商签名，签名失败中止。尚无可信签名新版交付，不因本次修复强制管理员安装。
- **验证**：名称相关新增 13 项检查，核心测试共 **405/405** 通过；Windows ARM64 / x64 应用构建均 **0 警告、0 错误**。签名链路的隔离检查及测试运行时见开发日志。双机名称同步、刷新按钮动画和窄窗口显示仍待原生界面复验。

旧仓库 `download/`（现 `Release/Windows/1.2.0/`）安装包及其校验信息没有替换，仍对应下文的 **392 项交付基线**。虚拟机从共享网络改为 Wi-Fi 桥接、按用户要求停止两个旧测试实例，仅属于本机环境处理，不是随安装包自动执行的行为。

## 已知安装限制（交付后反馈）

另一台 Windows 电脑反馈安装时出现 **Error 4551：应用程序控制策略已阻止此文件**，安装器尚未进入应用运行阶段。当前交付仍为未签名测试包，可能被智能应用控制或单位应用策略直接阻止；具体策略需读取报错电脑的应用控制日志确认，本机虚拟机未启用智能应用控制的检查不能替代目标电脑验收。

后续用户确认：**同一报错电脑以管理员身份运行现有安装包后安装成功**，本次无需先购买代码签名证书。该结果作为用户安装反馈记录，不等同于完整的启动、收发、升级或卸载验收；具体策略与执行环境差异仍未通过日志确认，不再将缺少可信签名视为本次故障的既定根因。

签名链路修复仍保留在源码，供后续可信发行使用；现有安装包未替换，不将安装器默认改成强制提权。其他电脑若仍受阻，处理步骤与依据见 [安装 Error 4551 说明](README.md#安装出现-error-4551)。

## 安装与资料保留

1. 按电脑架构选择安装包。旧版本仍运行时，先在应用的“设置 → 应用运行”退出，再安装并启动新版，避免文件占用和重复设备。
2. 新安装按两页引导确认名称、接收位置和连接准备；旧有效资料直接进入主界面并提示核对设置。防火墙提示按实际受信网络允许应用访问，无需关闭防火墙。
3. EXE 版资料继续保存在 `%LOCALAPPDATA%\Songli\FeigeTransfer`，收到的文件在设置的接收目录。覆盖安装/卸载的设计保留这些资料；MSIX 的资料与 EXE 渠道独立，不自动迁移身份或记录。
4. 无法发现时，可用真实局域网地址与当前端口手动连接。VPN/TUN/透明代理请检查局域网绕过规则；不同子网、双层 NAT、访客网络和设备隔离仍取决于实际路由策略，不能保证仅输入 IP 就能连通。
