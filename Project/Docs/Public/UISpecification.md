# 跨平台 UI 与交互同步规范

2026-10-23，基于 macOS 0.3.3 的实际 SwiftUI 实现整理，供 WinUI 3 同步。本文描述共同产品行为；系统菜单、凭据保护、文件选择器和文件管理器使用各平台原生能力。协议以[通信协议 v3](ProtocolV3.md)为准。

## 1. 当前体验与同步范围

主流程为：启动并准备设备身份 → 自动发现附近设备 → 一方请求连接 → 接收方同意一次 → 在同一会话中聊天、互传图片和文件。无配对密码、无 SAS 输入、无逐文件批准。关闭连接后授权失效，再连接须重新同意。

这是“设备会话 + 文件消息”界面。当前一次只连接一台设备；历史可按设备切换查看。没有群聊、离线投递、已读回执、语音视频或多设备同时在线聊天。不能照搬飞书/钉钉中尚未实现的按钮。

## 2. 桌面布局及主题

| 区域 | 当前 macOS 实现 | Windows 同步要求 |
| --- | --- | --- |
| 主窗口 | 单一主会话窗口，最小 960 × 680 逻辑点 | 原生单主窗口；缩放和高 DPI 下不挤压消息或按钮 |
| 左侧栏 | 宽 238；设备会话、附近设备、手动连接、传输记录、本机名称和设置 | 保持信息层级；WinUI 原生导航/列表即可，不强求相同像素 |
| 会话头部 | 设备名、连接阶段、请求/取消/断开操作 | 状态和动作随当前选中会话变化 |
| 消息区 | 按时间排列；我发的在右，对方的在左，姓名与时间在气泡外 | 可滚动，切换会话及新消息时定位底部 |
| 输入区 | 图片/文件选择、文本框、发送按钮、换行提示、拖放区域 | 原生输入法与附件拖放；不要以 WebView 替代原生业务界面 |
| 浅色主题 | 侧栏不透明白色，细分隔线，选中会话为强调色 13% 淡底 | 不使用大面积灰色侧栏；正文、次要文字、图标保持可读 |
| 深色主题 | 使用系统背景与文字色，随系统切换 | 使用系统暗色资源，不能把白色侧栏强套到暗色模式 |

Mac 的会话名 13pt、头部 17pt、正文 14pt；消息最大宽 420，附件卡片宽 310，内容边距 24。上述值供视觉参考，不是协议或 Windows 必须照抄的布局常量。选中态还应通过控件语义表达，不能只靠颜色。

## 3. 启动、设置和窗口生命周期

首次启动遵循[首次安装引导方案](FirstRunOnboarding.md)的两页目标流程，用户确认本机设置并看到权限用途说明后再触发身份准备及网络启动。下述正常运行的后台驻留规则在首次引导结束后适用；引导未结束时关闭窗口应停止初始化并退出。方案待两端实现与验收。

### 身份准备

- 启动时后台读取/创建设备身份，并执行真实随机挑战签名及验签；成功前不监听、不广播、不允许主动连接，界面可响应。
- 准备中显示“正在准备安全连接”及系统授权提示；失败显示原因和“重新授权”，无需强制退出应用。
- Mac 系统钥匙串弹窗输入的是 Mac 登录密码，不是应用配对密码。选择“始终允许”可避免重复授权；单次允许、应用更新或系统重新锁定仍可能再次询问。应用不读取或保存该密码，不导出私钥，不放宽访问控制。
- Windows 使用自己的安全凭据存储与后台签名预检，不复制 Mac 密码弹窗。两平台均缓存运行时身份，重连不能重新生成设备身份，也不能每次连接都触发凭据读取。
- 应用退出或取消后，晚到的身份准备结果不能重新启动监听。

### 设置

版本与更新入口、提示状态、下载与安装确认、等待收发结束的行为，统一遵循[应用更新规则](UpdatePolicy.md)；实际接入状态以平台开发日志为准。

设备名去首尾空白后为 1–48 个字符、UTF-8 ≤128 字节，拒绝控制字符；接收目录需可创建。必须先持久化成功再更新界面，失败保留原值并在设置窗口内提示。改名不能改变设备指纹或合并历史。Mac 菜单和侧栏设置入口打开同一个设置窗口。

### 窗口

关闭主窗口后应用保持运行，当前连接可继续；退出应用才关闭网络并清理未完成文件。Mac 点击 Dock 或“文件 → 显示主窗口”（⌘1）恢复主窗口，最小化时还原；即使设置窗口可见也要恢复主窗口，重复点击不创建多个主窗口。Windows 提供等价的任务栏/再次启动恢复行为；若采用托盘，需明确保留可返回入口并验收。

## 4. 会话列表、身份与连接状态

- 会话按完整 SPKI SHA-256 指纹归组，同名设备不得混在一起；附近发现仅是待连接入口，不能作为已认证身份。
- 列表显示设备名、最近消息/附件摘要，活动连接有状态点。两端当前都没有未读数和逐条消息通知；“收发完成通知”是首次收发后邀请启用的可选项，不是未读系统。
- 可打开其他设备历史，但输入和附件控件只能对已连接的当前会话启用。已连接 A 时，不能把查看 B 的操作误发给 A。
- 连接另一台设备前先断开当前连接；当前不自动切换或同时连接多台。
- 连接阶段：建立网络 → 交换设备信息 → 验证本机身份/系统授权 → 等待对端身份验证 → 等待对方同意 → 已连接。界面不要把等待人类授权笼统显示为网络传输中。
- 接收方只出现一次连接请求，展示对端名称和接收位置，操作为“拒绝”“同意连接”。发起方不再次确认自己发起的请求。
- 手动连接输入对端局域网 IP 与端口；地址、端口可在侧栏查看。输入错误在表单内说明；应用不接受公网地址/任意域名重定向。

## 5. 文字消息

| 动作/状态 | 行为 |
| --- | --- |
| 输入 | 原生多行文本框，支持中文输入法、选择、复制粘贴；组合输入尚未提交时，Enter 应提交候选，不可提前发消息 |
| 发送 | Enter；Shift+Enter 换行；也可点“发送” |
| 空消息 | 全空白禁止发送 |
| 长度 | 单条正文最多 8192 UTF-8 字节；超出给出提示并保留草稿，长文可发文件 |
| 内容 | 保留原始 Unicode、换行与空格；按纯文本显示 |
| 草稿 | 按选中会话保存且持久化到本机，重启后仍在；不能切换设备后串稿；发送成功后清除 |
| 发送中 | 不把本地写入 socket 当作送达；当前一次等待一条本机文字回执，可继续编辑下一条草稿 |
| 已送达 | 对端验证、记录成功并发回匹配 UUID 的回执后显示；不表示“已读” |
| 失败 | 显示未完成与重试；重新连接同一设备后可重试 |
| 重试 | 文字复用原消息 UUID，接收端按设备/方向/UUID 去重，去重受历史保留窗口限制 |

文件发送期间仍能聊天；文字、文件分块与机器回执共享有序加密写队列，不能因附件大而锁死文本输入。

## 6. 图片与普通文件

- 输入区分别提供“图片”“文件”选择入口，也可拖入本地图片/文件。当前只支持文件 URL 附件，不支持目录或剪贴板图片粘贴。
- 图片原始字节传输，不重压缩。按 `kind=image` 显示；接收成功后生成有界缩略图（Mac 最长边 640 像素，显示区域最多 282 × 220），后台解码，不能把大图完整解码到 UI 线程。
- 图片不支持预览、文件已移走或被删除时仍保留附件信息，不能显示伪造预览；Mac 当前提供无法预览提示并可尝试打开原图，需补充实体机文件移走场景验收。
- 图片预览和“打开原图”使用原始文件；普通文件提供“打开文件”“在文件管理器中显示”（Mac 为访达）。
- 普通文件卡片显示名称、大小、方向、时间、状态；活动卡片显示进度。Mac 尚无真实速度/剩余时间统计，不应复制早期草图中的演示数值。
- 附件按队列发送；每方向同时一个文件，两个方向可并发。选择多批附件需等当前发送批次结束；活动接收不阻止本机发送。
- 文件无产品大小或总时长上限，允许 0 字节；仍受实际磁盘、文件系统、分块长度和空闲超时约束。不得恢复 100 MiB、100 个文件或 30 分钟等旧阈值。

### 文件消息状态

`queued → sending → delivered`（发送方）或 `sending → received`（接收方）；失败/取消/断线转 `failed`。接收进度到 100% 不等于成功：必须消费 finish、校验总长度与 SHA-256、刷新落盘并原子提交，再发送回执。

取消传输会断开整条连接，因此会中断该连接上的双向活动传输；未提交暂存文件清理，已完成文件保留。文件重试重新传输，不是断点续传。卡片重试会产生一次新的发送记录；不得声称文件具有文字式去重或 exactly-once 保证。

## 7. 本机记录和兼容

会话记录本机保存，保留最近 1000 条已结束消息以及全部活动项；不能因历史裁剪丢失仍在队列中的文件。重启后未完成项标记失败。原版文件传输记录仍可从“传输记录”查看。

存储 JSON 结构无需两平台相同，但消息 UUID、指纹、方向、类型、状态与回执语义必须一致。没有云端记录同步。0.3.x Mac 使用 v3；v1/v2 客户端不能与之连接，不可静默降级到旧配对流程。

## 8. Windows 同步顺序与交付验收

1. 协议先支持 v3：12 字节 nonce、连接决定、可复用单读循环、带 ID/offset 的文件块、最终摘要、文字/回执与图片 kind；保留旧 v1 测试，避免混用向量。
2. 身份持久化与启动签名预检、TCP 监听与发现；验收本机回环，再验收两台物理机。
3. 将已有 WinUI 收发/设置界面改为设备会话布局和一次同意连接，验证后台运行和重开入口。
4. 接入文本和图片/文件卡片，验证 Enter/换行/中文输入法、拖放、原图打开、重试、草稿和会话隔离。
5. 完成以下双向验收后才可标记 Win↔Mac 互通。

- [ ] Mac→Win / Win→Mac：一次同意，多批附件及文字消息；聊天与双向文件可并发。
- [ ] 同名设备不合并，查看其他会话不能误发；离线发送入口禁用。
- [ ] 空白/超长文字不丢草稿；emoji/中文/多行往返一致；重试不重复接收文字。
- [ ] 图片按原图校验，缩略图后台生成；文件移动/删除、异常图片和大图有明确表现。
- [ ] 0 字节、大于 100 MiB 的文件、同名文件、磁盘不足、权限撤销、取消/断网，均无伪成功或覆盖已有文件。
- [ ] 授权未完成不开放网络；一端授权较慢不会被普通网络超时提前中断。
- [ ] 浅色/深色、高 DPI、长设备名、窗口重开、设置失败重试。

## 9. 证据边界

Mac 99 项自动测试通过（0.4.0：应用 54、核心 45，Bonjour 1 项按条件跳过），覆盖真实本机 TCP、发现、消息/附件、设置兼容、草稿、通知降级、记录、授权准备、窗口回调与更新验签/下载校验；0.4.0 设置窗口已在真实数据副本中逐卡片确认，更新链路完成本机回环实测。用户反馈启动授权后的连接测试成功，但未声明具体双机/跨平台矩阵。系统密码真实弹窗、拖拽/预览和完整实体双机 UI 验收仍不能以模型测试代替。Windows 2c37f61 已有 v1 原生收发/设置、DNS-SD、DPAPI、通知/记录及签名 MSIX，报告 189 项测试；这些已有能力需升级复用，不能据此认定已支持 v3 会话式文字/图片 UI。
