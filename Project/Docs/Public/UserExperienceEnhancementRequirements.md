# 新手引导、群成员交互与用户头像需求

状态：用户已批准；Windows WinUI 构建与 App/Core 测试已验证，完整界面验收仍待进行  
整理日期：2026-11-02  
适用平台：Windows（WinUI 3）与 macOS（SwiftUI）

本文整理三项体验改进：首次使用引导、群成员管理交互、本地预置用户头像。它补充现有[首次安装引导方案](FirstRunOnboarding.md)、[跨平台 UI 与交互规范](UISpecification.md)及[多人会话开发计划](MultiUserConversationPlan.md)，不替换其已有的身份、文件、连接同意和群组协议规则。两端使用各自原生控件，实现相同的产品行为。

## 1. 设计目标

- 用户先完成“找到设备、开始传输”，只有默认自动发现失败时才接触网络诊断或手动地址。
- 管理群成员时留在当前群聊上下文中，能直接认出成员、群主和可执行操作。
- 用户头像帮助区分设备与成员；提供本地预置选择，不要求上传照片或注册账号。
- 显示名称、头像和在线状态都是展示信息，不能代替完整设备指纹、连接同意或群成员权限。

## 2. 现状与约束

- 现有首次引导已包含设备名称、接收目录、身份准备和局域网授权说明。本需求保留该流程，只补充更易懂的自动发现说明及可选头像。
- Windows 与 macOS 已有群组会话和成员变更能力。群组最多 20 名成员（包含本机）；只有群主能提出成员名单变更，其他成员通过申请退出。加入邀请和群组事务仍须按现有协议获得确认并完成提交。
- 当前界面已有群组页面或群成员操作入口，但成员展示和操作较分散；Windows 主要用文字名单和独立变更对话框，macOS 主要通过成员菜单管理。
- FeigeTransfer 是无账号的局域网点对点应用。首版不增加部门、团队目录、云端联系人或自动建群；群成员由用户明确选择。
- v4 群组控制消息会拒绝未知字段。因此头像需求不得通过静默改变 v4/v5 群组控制消息来实现。

## 3. 需求一：首次使用引导

### 3.1 保留既有设置流程

- 保留设备名称和接收文件夹设置、身份准备、系统权限说明及“稍后设置”能力；不新增账号、密码、配对码或强制收发测试。
- 首次使用的文案以日常任务为中心。网络参数、子网和端口不作为首次设置必填项。
- 可在第一步加入可选头像选择，用户可以跳过。头像选择不得阻塞引导，也不得改变已有用户的引导完成状态。

### 3.2 自动发现与空状态

- 身份和网络服务准备完成后自动搜索附近可连接设备；不能要求用户先手动填写 IP 或端口。
- 主界面明确展示附近设备及连接状态。没有发现设备时说明“尚未找到设备”，不直接断言是防火墙或权限问题。
- 空状态提供“重新搜索”“检查另一台设备是否已打开并处于可互通网络”“连接排查”等下一步；手动输入地址放在次级或高级入口。
- 设备发现成功不代表已连接。用户仍需明确选择设备并发起连接，接收方仍按现有规则同意一次。
- 不在引导中创建群组、发送样例消息或制造虚假的成功状态。首次操作提示可关闭，且只在真实业务状态下出现。

## 4. 需求二：群成员管理交互

### 4.1 在当前群聊内管理

- 从群聊标题或成员入口打开成员管理侧栏、检查器或平台原生等价面板；打开面板时保留当前群聊上下文，不跳转到独立管理页面。
- 面板顶部显示群名称和“成员数/20”；成员区域显示头像、显示名称、群主标记及当前连接状态。
- 群成员较多时提供“查看全部成员”入口；完整名单可按显示名称搜索。设备指纹只放在需要诊断或核对身份的次级详情中。
- 常用操作提供可见文字标签，例如“添加成员”“移出群聊”；避免只靠加号、减号或无标签图标表达含义。

### 4.2 权限与事务状态

- 群主可添加或移除成员；非群主显示“申请退出群聊”。当前协议没有管理员角色，本需求不新增管理员权限。
- 添加成员仅从符合现有连接条件的设备中选择；清楚说明受邀设备需要接受邀请，且新成员只有在成员事务提交后才成为正式成员。
- 移除操作须明确指出目标成员，并在提交前确认。等待群成员确认或提交失败时，显示“处理中／待确认／失败，可重试”等真实状态；不得提前显示成员已成功加入或移除。
- 成员名单仍遵循现有群主权限、全员成员事务、连接要求及 v4/v5 兼容边界。UI 不能绕过确认、自动批准或静默降级。
- 面板和名单支持键盘操作、读屏名称及浅色/深色主题；状态除颜色外还须有文字说明。

## 5. 需求三：本地预置用户头像

### 5.1 素材与设置

- 首版提供 10 个应用内置头像：`bird`、`cat`、`fox`、`panda`、`bear`、`fish`、`rocket`、`sun`、`star`、`leaf`。两端使用相同素材映射，在浅色和深色背景上均清晰。
- 用户可在首次引导中选择，也可稍后在个人资料/设置中更换；头像不是必填项。
- 首版不要求自定义照片上传，不访问照片库，不依赖互联网下载头像。
- 保存稳定的 `avatarId`，两端使用同一组 ID 和对应素材。未知或缺失的 ID 使用默认头像；没有头像时也可用显示名称首字作兜底。

### 5.2 展示与身份边界

- 同一用户头像在设备/会话列表、连接对象确认、群成员预览与完整名单、群消息发送者标识中保持一致，并始终同时显示可读名称。
- 更换头像不改变设备指纹、群主身份、连接授权、历史消息或成员关系；头像只用于展示，不能作为认证或授权依据。
- 不把头像图片文件发给其他设备；如需跨设备显示用户选择的头像，只传播稳定的头像 ID，并在接收端从内置素材库解析。

## 6. 已批准的跨设备头像展示范围

用户已批准采用“向局域网联系人展示”的方案：传输稳定的 `avatarId`，不传头像图片。两端统一使用以下 10 个预置 ID：`bird`、`cat`、`fox`、`panda`、`bear`、`fish`、`rocket`、`sun`、`star`、`leaf`；未知或缺失值回退到 `bird`。

- 复用现有 Bonjour/mDNS TXT 发现记录中的可选 `avatar=<avatarId>` 字段。旧版本可忽略该键；缺失或未知 ID 不影响发现、连接、审批或群组操作。
- TXT 内容属于未认证的展示提示。持久化对端头像时，必须先由完整的 64 个十六进制字符设备指纹与已认证连接身份匹配；不以实例名、显示名称、指纹前缀或头像 ID 建立身份。
- 头像只用于 UI。不得据此批准连接、邀请或成员变更，也不得改变设备身份、群主身份或历史消息归属。
- 不更改 Protocol v4/v5 的群组控制消息或消息向量；头像元数据不得成为协议兼容条件。

## 7. 不纳入本次范围

- 账号注册、部门/团队通讯录、云端头像存储或群成员自动同步。
- 自定义照片上传、头像裁剪服务、头像图片传输。
- 新增群管理员角色、改变群人数上限或改变群组成员事务协议。
- 自动连接设备、自动接受连接/入群邀请、关闭系统防火墙或静默修改系统网络设置。

## 8. 验收标准

- 新用户无需配置网络参数即可完成引导；没有发现设备时，界面能提供重新搜索和针对性排查入口，且不会把“未发现”误报为权限拒绝。
- 可跳过头像选择；所选头像在重启后保留，已有用户升级后不被强制重走引导。
- 两端内置素材 ID 对应相同视觉头像；未知 ID 和未设置头像都有稳定、可读的回退样式。
- 群聊中可在不离开当前会话的情况下打开成员面板，看到成员数、成员头像/名称、群主标记及连接状态。
- 群主可发起加人/移除；非群主可申请退出；目标成员、全员确认和事务结果清楚可见，未提交的变更不会伪装成完成。
- 头像与姓名并列显示，头像变化不会改变设备身份或权限；失败、离线和旧客户端缺少头像资料时仍能正常连接及管理群组。
- 浅色/深色、高 DPI、键盘和读屏操作均可使用，图标操作有文字或无障碍标签。
